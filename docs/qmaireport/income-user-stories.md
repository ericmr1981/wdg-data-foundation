# 收入分析页 — 用户使用故事

---

## 用户画像

| 角色 | 关注点 | 操作频率 |
|---|---|---|
| 财务主管 | 各渠道收入总额、银行实际到账率是否正常 | 月/季末 |
| 运营人员 | 各门店各渠道的银行入账是否滞后、未结算订单 | 每周 |
| 会计 | 对账：银行流水逐笔 vs 平台订单 | 月底对账期间 |
| 系统管理员 | 检查分类规则是否准确、是否有异常科目 | 新规则部署后 |

## 故事 1: 月度收入总览

**用户:** 财务主管  
**场景:** 每月初查看上月各品牌总收入情况  
**操作流程:**

1. 选择时间粒度「按月」、期间「2026-04」
2. 看到顶部三张卡片：
   - 收款总金额 → 该期间银行流水总收款
   - 营业收入 → 主营业务对应的银行入账
   - 其他收入 → 利息/退款/注资等非主营收入
3. 查看二级分类占比条，确认各渠道收入比例是否合理
4. 如果有渠道占比异常偏高/偏低，记录为待排查问题

**关键数据:** `GET /api/financial/income-metrics` 按 `累计截止` 模式汇总

---

## 故事 2: 银行入账率监控

**用户:** 运营人员  
**场景:** 每周查看各渠道的银行实际到账率，发现超期未入账的趋势  
**操作流程:**

1. 滚动到「银行入账率」区块
2. 看到各渠道卡片：
   - 企迈实收 = 平台的订单金额
   - 银行入账 = 银行实际到账
   - 入账率% = bank / qimai × 100
3. 绿色卡片（95%~110%）→ 正常
   - 黄色卡片（90%~95%）→ 注意
   - 红色卡片（< 90% 或 > 110%）→ 需要排查
4. 查看折线图确认趋势：如果某渠道连续数月入账率下降，说明结算出现问题

**常见观察:**
- 美团/饿了么入账率通常接近 100% 或略低（有平台抽成/退款）
- 其他渠道（现金存现）可能有波动
- 入账率 > 100% 通常是因为银行到账包含了上期未结算的订单

**关键数据:** `GET /api/gelatomiiix/income/bank-entry-stats`

---

## 故事 3: 追踪"营业款结算"到账

**用户:** 会计  
**场景:** 发现"营业收入/其他渠道"金额较大，想确认具体是哪些款项  
**操作流程:**

1. 在左侧对方科目列表，找到「营业收入 > 营业款结算」（counterparty_name 来自银行流水）
2. 点击后右侧展开流水明细
3. 按月份浏览：摘要通常为"营业款结算"，金额为某平台结算净额
4. 如果该笔款项该归入微信/支付宝等标准渠道，尝试在规则管理中添加对应规则

**关键数据:** `GET /api/financial/counterparty?direction=in&counterparty=营业款结算`

---

## 故事 4: 未入账订单排查

**用户:** 运营人员  
**场景:** 发现某渠道入账率偏低，想确认是否有平台订单未结算  
**操作流程:**

1. 当前渠道入账率卡片显示红色（如 85%）
2. 确认「银行入账率」区块下方的月度趋势——企迈线上曲线持续高于银行入账曲线
3. 检查未入账订单明细（`third_party_txn_no IS NULL`）
4. 如果某月有大量未入账订单，联系平台或银行确认结算进度

**关键数据:** `bank-entry-stats` API 的 `unmatchedOrders` 子查询

---

## 故事 5: 按门店筛选分析

**用户:** 区域经理  
**场景:** 比较不同门店的收入结构和入账情况  
**操作流程:**

1. 门店下拉选择具体门店（如 SH001）
2. 所有三个区块同时刷新：
   - 收入概览卡片 → 该门店的银行收款总额
   - 银行入账率 → 该门店的渠道入账情况
   - 对方科目列表 → 该门店的交易对手
3. 切换到另一门店对比
4. 如发现某门店其他渠道占比异常高，可能是分类规则有误

---

## 故事 6: 对账周期切换

**用户:** 会计  
**场景:** 季度/年底做财务报表时，需要查看累计数据  
**操作流程:**

1. 时间粒度切换到「按季」，选择「2026-Q1」
2. 收入概览区块显示 Q1 累计的银行收款
3. 对方科目列表显示 Q1 期间的主要收入和支出方
4. 可与利润表（v_profit_statement）交叉验证

**注意:** income-metrics API 使用累计截止模式，选 Q1 结果是 1月~3月整个季度的累计数据。

## 关于区块A与区块B金额对不上的说明

用户使用中一个常见的困惑是：

**问题: 区块A"营业收入/其他渠道"的金额 和 区块B"OTHER"卡片的金额 为什么对不上？**

| | 区块A 营业收入 | 区块B 入账率卡片 |
|---|---|---|
| 数据来自 | 银行流水 (bank_txn) — 银行对账单实际到账 | 企迈订单 (income_detail) — 平台订单金额 |
| 分类依据 | 规则引擎多字段综合判定 → lvl1_code/lvl2_code | payment_methods 数组字符串硬编码映射 |
| OTHER的范围 | OTHER_CH: 存现、结算、补贴等非标渠道 | 无法匹配7种支付方式的订单（含未知支付方式） |

**正确理解:**
- 区块A = 银行实际收到的钱，按分类规则打标 → 适合做财务报表
- 区块B = 平台应该收到的钱 vs 银行实际收到的钱 → 适合做入账监控

两套数据口径不同、来源不同、分类方式不同，金额不一致是预期行为。设计上区块B的"入账率"已经是两者的关联指标。
